Detailed implementation plan

(Single payment, auto-assign driver, editable later by admin/employee)

Phase 1 — Database + entity model updates
Add nullable car extra driver fee

Cars.extraDriverFeePerDay (nullable decimal(10,2)).

Add driver daily fee

Drivers.dailyFeePerDay (non-null decimal(10,2) with a default, e.g. 20.00 so old rows don’t break).

Update entities

Car.cs → public decimal? ExtraDriverFeePerDay { get; set; }
Driver.cs → public decimal DailyFeePerDay { get; set; }

Phase 2 — Pricing rules (single source of truth)

Create a single pricing calculation used by:

Booking creation

Driver reassignment (admin/employee)

PDF / receipt display

Rules:

baseRental = PricePerDay * rentalDays

driverService = DriverDailyFee * rentalDays

carExtra = Car.ExtraDriverFeePerDay * rentalDays (only if not null AND HasDriver==true)

subtotal = baseRental + driverService + carExtra

discount = subtotal * promo%

total = subtotal - discount

Important:
DriverDailyFee is a snapshot stored on Booking and does NOT change automatically if the driver changes later.

Phase 3 — Driver assignment at booking creation (AUTO-ASSIGN)
Edit BookingManager.MakeBookingAsync

If HasDriver == true:

Auto-assign a driver BEFORE payment

Select driver using:

IsActive == true

Available for full booking dates

Allowed to drive the car’s category

No conflicting bookings

If no driver available → fail booking creation (do not proceed to payment)

On successful assignment:

booking.DriverId = selectedDriverId

booking.DriverDailyFee = selectedDriver.DailyFeePerDay (snapshot)

Pricing includes:

base rental

driver service

car extra driver fee (if exists)

Trip creation:

Create Trip record immediately (TripStatus = Pending)

Payment behavior (single payment only)

Create Stripe Checkout Session immediately

Charge full total (car + driver + car extra fees)

No second payment, no deferred payment, no “pay later”

Security:

Ignore requestDto.DriverDailyFee (client must not set fees)
